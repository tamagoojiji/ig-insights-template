# 法的整理（IGインサイト保存テンプレート）

本ドキュメントは、本テンプレートの設計思想と「やっていること／やらないこと」を、規約・法令の観点で整理したもの。配布時のFAQ・利用者からの問い合わせ対応の根拠として使用する。

## 結論（要約）

| 区分 | 行為 | 本テンプレートでの扱い |
|---|---|---|
| 🟢 白 | Instagram Graph API（Meta公式・規約準拠）の正規利用 | ✅ 採用 |
| 🟢 白 | 自分のビジネス/クリエイターアカウントのデータを自分のスプシ・自分のDriveに保存 | ✅ 採用 |
| 🟢 白 | Meta公式「アカウントセンター → 情報をダウンロード」zipの正規エクスポートをパース | ✅ 採用（メニュー「📦 Meta公式zipアップロード」） |
| 🟢 白 | BYO型（Bring Your Own credentials）— 利用者が自分でMeta App・自分でトークン管理 | ✅ 採用（クリエイター側に送信されない） |
| 🟡 グレー | Business Discovery API — 公開アカウントの基本情報のみ取得可（規約上は許可） | ❌ **不採用**（rate limit厳しく、用途次第で警告リスク） |
| 🟡 グレー | フォロワーのコメント本文・他人のキャプション保存 | ❌ **不採用**（個人情報保護観点。自分のキャプションのみ保存） |
| 🔴 黒 | HTMLスクレイピング（instagram.com を直接叩いてDOM解析） | ❌ **絶対やらない** — Meta規約違反 + 不正アクセス禁止法 + IP BANリスク |
| 🔴 黒 | 第三者の非公開アカウントデータ取得 | ❌ **絶対やらない** — 完全違法 |
| 🔴 黒 | アクセストークン集中管理（全利用者分を1サーバ保持） | ❌ **絶対やらない** — Metaプラットフォーム規約違反リスク |
| 🔴 黒 | 自動コメント・自動DMの大量送信 | ❌ **絶対やらない** — スパム規約違反 |

## 詳細

### 🟢 白の根拠

#### 1. Instagram Graph API の正規利用
- 提供元: Meta（旧Facebook）公式
- ドキュメント: https://developers.facebook.com/docs/instagram-api
- 利用要件: ビジネス/クリエイターアカウント + 連携Facebookページ + Meta開発者アプリ + 適切な権限（`instagram_basic` / `instagram_manage_insights` 等）
- 自分のアカウントのみを取得対象とする「開発モード（テスター追加）」で運用するため、アプリ審査は不要

#### 2. 自分のデータを自分のストレージに保存
- 取得対象: 利用者本人のビジネス/クリエイターアカウントの投稿（フィード・リール・ストーリーズ）とインサイト数値
- 保存先: 利用者本人のGoogleスプレッドシート + 利用者本人のGoogleドライブ
- 配布元（クリエイター）はトークンもデータも一切預からない

#### 3. Meta公式「データダウンロード」zipの取り込み
- Metaは利用者本人に対して **アカウントセンター → 情報をダウンロード** で、自分の投稿データの正規エクスポート機能を提供している
- このzipは Meta が公式に発行する正規データであり、それをパースして自分のスプシに整形する処理は完全に合法
- ストーリーズ（API上24時間以内のみ取得可）の過去データを復元するための唯一の正規ルート

#### 4. BYO型（Bring Your Own credentials）
本テンプレートは以下を**すべて利用者自身**に用意・管理してもらう設計:

- Meta Developer App（自分のMetaアカウントで作成）
- Instagram Graph API アクセストークン（自分のScript Properties内に保管）
- Google アカウント・スプシ・Driveフォルダ
- Gemini API キー（OCR用・任意）
- Discord Webhook URL（通知用）

→ 配布元（クリエイター）はトークンを一切預からないため、Metaのプラットフォーム規約（トークン集中管理禁止）に抵触しない。利用者本人と Meta の二者間関係のみで完結する。

### 🟡 グレーの根拠と本テンプレでの方針

#### Business Discovery API（競合追跡）
- Graph API の `business_discovery` エンドポイントを使うと、公開Instagramアカウントの基本情報（フォロワー数・投稿数・直近メディア）を取得可能
- 規約上は許可されているが:
  - rate limit が厳しく頻繁に叩くとアプリ警告
  - 用途次第（マーケ目的での競合監視はOK / 個人特定や嫌がらせはNG）でグレー
- → **本テンプレでは採用しない**。利用者が「競合追跡したい」と相談してきた場合、別途SaaS版（VPS分離・マルチテナント）を案内

#### フォロワー・他人のキャプション保存
- フォロワーのコメント本文や他人の投稿のキャプションを大量保存すると、個人情報保護法・GDPR等に抵触する可能性
- → **本テンプレでは自分のキャプションのみ保存**。コメント本文は保存対象外

### 🔴 黒の根拠（絶対やらないこと）

#### HTMLスクレイピング
- instagram.com / instagram.com/p/... を直接 fetch して DOM 解析する手法
- **規約違反**: Meta利用規約で明示的に禁止
- **不正アクセス禁止法**（日本）: 認証回避の意図がなくても、サービス側の意図しない自動アクセスとして問題視される事例あり
- **IP BAN**: Meta の bot 検知でアクセス遮断・アカウント凍結のリスク
- 取得できたデータの**正確性・継続性が保証されない**（DOM変更で即破綻）

#### 第三者の非公開アカウントデータ
- 友達限定・非公開設定のアカウントから何らかの方法でデータを取得 → 完全違法
- 本テンプレは「自分のビジネスアカウントのみ」が大前提

#### アクセストークン集中管理
- 配布元のサーバが利用者100人分のIGアクセストークンをDBに保持して代理アクセス
- → Meta プラットフォーム規約違反のリスク（プラットフォーム条項3条等）
- → 本テンプレが BYO型 を採用する根本理由
- ※ 別プロジェクトの ig-insights-saas は VPS+Docker分離で**利用者ごとの専用環境**を提供する形でこの問題を回避している。本テンプレ（マスタースプシ配布）とは別アーキテクチャ

#### 自動コメント・DMスパム
- Graph API で自動コメント投稿は技術的には可能だが、大量送信はスパム規約違反
- → 本テンプレは**読み取り専用**。一切の書き込み（投稿・コメント・DM）を行わない

## 利用者責任（明示事項）

setup-guide.html および購入時の利用規約で以下を明示:

- Meta App の作成・審査・規約遵守の責任は利用者にある
- Gemini API 等の外部API使用料は利用者負担
- IG Graph API の仕様変更・廃止に対しては本テンプレも追従更新を行うが、保証はベストエフォート
- 取得データの利用方法（再配布・公開等）は利用者の判断と責任において行う

## 「ユーザーの現状」評価

ユーザー（@tamago_usj_guide）の現在の運用 = 自分のIGビジネスアカウントを Graph API で取得・自分のスプシに保存 = **完全に白**。本テンプレートはこの設計を BYO型で他者にも使えるように汎用化したもので、汎用化版でも同じ設計を貫くため白のまま。
