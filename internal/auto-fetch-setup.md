# IGインサイト 自動取得 + 自動OCR セットアップ（汎用手順）

クライアント納品時・初回セットアップ時に共通で適用する手順。
**新しい投稿（フィード・リール・ストーリーズ）を30分ごとに自動取得し、ストーリーズは取り込みと同時に画像内テキストをOCRする**仕組みを動かすための最短セットアップ。

過去分の取り込みは含まない（必要なら別途「📚 過去全件取り込み（API）」「📦 Meta公式zipアップロード」を1回実行）。

---

## 前提（事前に揃っていること）

1. GASプロジェクトに最新コードが反映済み（`clasp push` または GASエディタからの貼付）
2. スクリプトプロパティに以下が設定済み
   - `IG_ACCESS_TOKEN`（長期トークン）
   - `IG_USER_ID`（接続テストで自動取得可）
   - `FB_APP_ID` / `FB_APP_SECRET`（トークン更新に必須）
   - `DRIVE_FOLDER_ID`（Drive画像保存先）
   - `GEMINI_API_KEY`（OCRに必須・他プロジェクトと共有可だがレート注意）
   - `WEBHOOK_URL`（任意・Discord通知）
3. シート構成が初期化済み（メニュー「🔧 初回セットアップ（シート作成）」を1回）
4. 「🔗 接続テスト」が成功している

## セットアップ（1ステップ）

スプシメニュー「📊 Instagram Insights」→ **「⏰ トリガーをインストール」**

これだけで以下が登録される（既存の同種トリガーは内部で削除→再作成）:
- `autoFetch` — **30分ごと**にインサイト取得（フィード / リール / ストーリーズ）
- `refreshTokenJob` — **毎週日曜 9時**にトークン更新

確認: メニュー「📋 トリガー一覧」で上記2件が出ればOK。

注意: `installTriggers` は `TRIGGER_HANDLERS = ['autoFetch', 'refreshTokenJob', 'autoOcrTick_']` を全削除してから再作成する。**過去分OCR用の `autoOcrTick_` トリガーが残っていれば、このタイミングで一緒に止まる**。

---

## 動作仕様

### autoFetch (30分ごと)

`gas/main.js` の `autoFetch()` が以下を実行:

1. `checkAndRefreshToken()` — 必要ならトークン延長
2. `fetchAndWriteFeed()` — 新規フィード/リールを追加、既存は経過時間に応じて更新
3. `fetchAndWriteStories()` — 新規ストーリーズを追加 + **その場でOCR**

### 新規ストーリーの OCR（インライン実行）

`gas/stories.js:100-` で新規行ごとに:

1. 画像を Drive に保存（成功時のみ）
2. Drive URL を `ocrImage_()` に渡して Gemini で文字起こし
3. P列「画像内テキスト」に結果を書き込む
   - 成功: 抽出テキスト
   - 空文字応答: `[OCR_EMPTY]`
   - 画像保存失敗: `[画像なし]`
   - Gemini側エラー: `[エラー] {message}`

### OCR利用モデル

`gas/ocr.js:5` — `gemini-2.5-flash`（無料枠で十分。ストーリー数件/日のペースなら他のGemini処理に影響なし）

## 既存行をあとからOCR/修復したいとき

- 一括バッチ: メニュー「🔍 ストーリーズOCR一括」（5分制限内）
- 件数指定: メニュー「🔍 ストーリーズOCRバッチ（件数指定）」
- 自動全件: メニュー「🤖 自動OCR開始（5分おきに100件）」→ 完走後に自動停止
- 進捗確認: メニュー「📈 自動OCR進捗」
- 緊急停止: メニュー「🛑 自動OCR停止」

⚠️ **大量バッチは Gemini レート制限に注意**。同じ `GEMINI_API_KEY` を他プロジェクトと共有している場合、無料枠（10〜15 req/分）を食い合う。必要なら:
- OCR専用 APIキーを別発行
- batch size を 100 → 30 等に下げる
- `ocrImage_` 呼び出し間に `Utilities.sleep(7000)` を挟む（約8.5 req/分に抑制）

## トラブルシュート

| 症状 | 確認ポイント |
|---|---|
| OCR列が空のまま | `GEMINI_API_KEY` 未設定 / autoFetchトリガーが入っていない |
| `[エラー] HTTP 429` | Gemini無料枠超過。時間を空けるか専用キー化 |
| `[エラー] GEMINI_API_KEY が未設定です` | スクリプトプロパティを設定 → リロード |
| `[画像なし]` | `DRIVE_FOLDER_ID` 未設定 or 画像URL期限切れ |
| サムネ列が空 | `DRIVE_FOLDER_ID` 未設定 or 取得時に時間切れ |
| 取得自体が動かない | トークン期限 / 「📋 トリガー一覧」で `autoFetch` 存在確認 |

## 過去分の取り込み（必要時のみ・1回実行）

- フィード/リール: メニュー「📚 過去全件取り込み（API）」を `BACKFILL_CURSOR` が消えるまで連打
- ストーリーズ24h超: Meta公式zip（アカウントセンター → 情報をダウンロード → JSON形式）→ メニュー「📦 Meta公式zipアップロード」

⚠️ 既知の未修正バグ（2026-05-13時点）:
- `backfill-api.js:appendMinimalRow_` はサムネイル列を埋めない（過去フィード/リールはサムネ空）
- `meta-zip-import.js:insertMetaItem_` は履歴シートにしか書かない（本体シートに出ない）

恒久対応する場合は別途修正してから過去取り込みを実行すること。
